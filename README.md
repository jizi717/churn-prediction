# 项目一：电信用户流失预测模型

## 一、业务背景
某电信运营商客户流失率持续高于行业均值，运营团队无法提前识别高风险客户，只能在客户提出离网后才做被动挽留。本项目目标：**在客户流失前预测其流失概率，输出可运营的高风险名单与分层策略**。

## 二、数据来源
- IBM Telco Customer Churn 公开数据集（真实电信客户数据）
- 7,043 名客户 × 21 个字段，整体流失率 **26.54%**
- 字段覆盖：在网时长、月费、总消费、合约类型、支付方式、增值服务订购情况等

## 三、技术栈
Python（Pandas / NumPy）· Scikit-learn · XGBoost · SHAP · Matplotlib · ECharts

## 四、分析流程
1. **数据清洗**：TotalCharges 空值按业务逻辑填补（在网时长为 0 的新客用月费替代），去重，类型标准化
2. **特征工程**（21 → 33 个特征）：
   - 基础特征：在网时长、月费、累计消费
   - 衍生特征：月均实际消费、资费变化幅度、生命周期进度、新客标识（在网 ≤6 个月）
   - 业务特征：增值服务订购数量、安全服务捆绑标识、光纤标识、月付合同标识、电子支票标识
   - 组合特征：高风险组合（月付 + 电子支票 + 光纤）
3. **建模对比**：逻辑回归（标准化 + 类别权重）→ 随机森林 → XGBoost（随机搜索 60 组参数 × 3 折交叉验证）
4. **评估**：AUC / KS / PR-AUC / 精确率 / 召回率 / F1，并用 PR 曲线寻找最优判定阈值
5. **可解释性**：Permutation Importance + SHAP 摘要图
6. **业务落地**：按预测概率十分位分层，计算 Lift 与捕获率，测算挽留收益

## 五、关键结果（全部由脚本真实计算）

| 模型 | AUC | KS | PR-AUC | 精确率 | 召回率 | F1 |
|---|---|---|---|---|---|---|
| 逻辑回归 | 0.8468 | 0.5372 | 0.6569 | 0.5129 | 0.7995 | 0.6249 |
| 随机森林 | 0.8471 | 0.5518 | 0.6542 | 0.5526 | 0.7727 | 0.6444 |
| XGBoost | 0.8465 | 0.5410 | 0.6621 | 0.5128 | 0.8021 | 0.6257 |
| **XGBoost（阈值 0.61）** | **0.8465** | **0.5410** | **0.6621** | **0.5841** | **0.7246** | **0.6468** |

- 3 折交叉验证 AUC：**0.8489**
- 最高风险分位（Top 10%）实际流失率 **75.18%**，Lift **2.83 倍**
- Top 20% 高风险客户覆盖 **50.27%** 的真实流失人群
- 高风险客户月均 ARPU：**78.0 元**
- 定向挽留收益测算（按 20% 挽留成功率）：测试集口径约 **3.52 万元/年**，外推全量 7,043 客户约 **17.6 万元/年**

## 六、核心业务洞察
- **合约类型是第一驱动力**：月付合同流失率 42.7%，一年期 11.3%，两年期仅 2.8%
- **新客最危险**：在网 0-6 个月客户流失率 52.9%，49-72 个月客户仅 9.5%
- **光纤用户流失率 41.9%**，显著高于 DSL（19.0%）——高价套餐体验未达预期
- **电子支票支付用户流失率 45.3%**，是自动转账用户（15-17%）的近 3 倍
- 订购安全服务/技术支持的用户流失率仅 14.6-15.2%，未订购者高达 41.8%

## 八、面试高频追问（务必准备）
1. 为什么 AUC 只有 0.847，还能更高吗？（答：Telco 数据集公开 SOTA 约 0.84-0.86，已接近上限；可尝试特征交叉、目标编码、 stacking）
2. 正负样本不平衡怎么处理？（scale_pos_weight、class_weight='balanced'；未用 SMOTE，因为 26.5% 的比例不算极端，过采样反而会破坏概率校准）
3. KS 值 0.54 代表什么？（好坏样本分布的最大分离度，>0.3 即有区分能力，>0.5 属优秀）
4. 阈值为什么选 0.61 而不是 0.5？（业务上精确率更重要，避免对大量低风险客户做无效触达；用 PR 曲线找 F1 最优点）
5. 模型上线后怎么监控？（PSI 特征稳定性、AUC 衰减、预测流失率与实际流失率偏差）
